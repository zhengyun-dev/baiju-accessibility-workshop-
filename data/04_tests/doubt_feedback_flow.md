# 存疑反馈分支 · 流程说明

## 为什么要有这个

工具 ② translate-to-plain 遇到拿不准的南京方言词会标 `（存疑：<原词>）`，**不硬译**（合规 3.4）。
但这些"存疑"词不能一直挂在那里——需要一个**人工/后续补来源**的闭环：
谁发现、存疑词是什么、最终释义是什么、来源 URL 是哪，记下来，回填知识库。

## 流程（5 步）

1. **发现**：② 生成译文后，凡带 `（存疑：X）` 的词进入 `存疑待办`（见 `pending.json`）。
2. **登记**：把 X 写入 `pending.json` 的 `items[]`，字段：词、所在唱词、暂存释义、待补状态。
3. **查来源**：人工/公开资料核实 X 的南京方言含义，**找到 URL**（维基/百科/非遗档案）。
   - 查不到 → 释义标 **"待考"**，不硬编。
4. **回填**：把"词 + 释义 + 来源URL"加进 `dialect_words_supplement.md`（② ⑤ 的方言词表会吃到）。
5. **销项**：`pending.json` 里该项 `status` 从 `pending` 改成 `resolved`，记 `resolvedDate` + `sourceUrl`。

## 铁律（合规 3.4）

- **没来源就标"待考"，绝不自己编释义。**
- 回填必须带 URL（维基/百科/官方非遗网等公开来源）。
- 歇后语谐音双关词（针好/顶好）单独归 `harmony`，不算"难词"，也不进 pending（本意游客可懂）。
